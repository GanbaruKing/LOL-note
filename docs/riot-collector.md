# Riot API収集ツール

## 実行

APIキーを設定したPowerShellでプロジェクトへ移動して実行する。

```powershell
npm run stats:collect
```

Riot IDを「名前#タグ」で入力する。既定はカタログのパッチ、日本サーバー（JP1）、Ranked Solo/Duo（420）、直近100試合の履歴。対象パッチは起動時に表示する。キーを引数・チャット・ソースコードに書かない。

```powershell
npm run stats:collect -- --patch 16.18 --count 500
```

countは1〜1000。最初の動作確認は100でよい。出力はプロジェクト内の `.riot-data/statistics.json`。アプリのStatistics →「統計JSONを取り込む」で選択する。自動でNotebookのデータを書き換えない。

キーが未設定なら、次の補助スクリプトで非表示入力もできる。実行ポリシーの変更は行わない。

```powershell
.\scripts\collect-statistics.ps1
```

このスクリプトが入力したキーは処理後に環境変数から削除する。事前に設定済みのキーは維持する。.env.exampleは変数名の案内であり、.envの自動読み込みはしない。開発キーは24時間で失効するため、403の場合は期限も確認する。

## 集計方法と限界

指定プレイヤーの履歴一覧を取得し、JP1の試合のみ、Match IDで重複排除する。各試合の同じteamPosition同士を対応させ、両側のChampionについて勝利数・試合数を集計する。選択パッチ以外、Solo/Duo以外、Summoner's Rift以外、5分未満、早期終了フラグ、役割の重複・欠損、不明なChampionを除外する。

これは指定プレイヤーの履歴から採集した標本であり、全体勝率・特定ランク帯の統計ではない。試合時点のランクは推測しない。100試合の履歴では各対面が100試合以上にならないことが普通で、アプリで行が表示されなくても収集失敗ではない。100試合閾値は維持する。大規模収集や複数プレイヤー標本の統合は後続作業。

出力は今回選んだ履歴を対象に毎回作り直す。過去の出力と自動合算しない。対象試合ゼロ・通信失敗時は既存の出力を維持する。取得済みの有効試合キャッシュは再利用するため、再実行で中断分を進められる。キャッシュには集計に必要なフィールドのみを保存し、PUUIDやプレイヤー名、APIキー、API応答全体は保存しない。

## 通信と保存

Asia routingの公式HTTPS APIだけを使用し、キーはX-Riot-Tokenヘッダーに送る。リダイレクト禁止、15秒タイムアウト、約1.3秒間隔、最大4回試行。429はRetry-After（秒、最大300秒）に従い待機し、繰り返す場合は停止。401/403では直ちに停止する。同じキーを別ツールで同時使用すると制限に達する可能性がある。

`.riot-data/`をGit対象外とする。JSONは一時ファイルから置換し、多重起動はcollector.lockで防ぐ。強制終了でロックが残った場合は、収集プロセスが終了していることを確認してからロックファイルだけを削除する。

## 検証と公開

テスト用応答で対面方向、重複排除、除外条件、Retry-After、秘密を含めないエラー、CLIからのJSON生成と既存Importer互換を確認。実API呼び出しはユーザーのPowerShellで実行する。実キーの有効性や実試合取得の成功はまだ未確認。

製品登録と公開用Production Keyは別の手続き。開発キー・Personal Keyでは公開運用しない。LCUを使用する製品も登録対象。配布バイナリにキーを埋め込まず、公開向け収集は管理側で行う設計とする。

- [Riot登録・キー管理ポリシー](https://developer.riotgames.com/policies/general)
- [キーの種別と制限](https://developer.riotgames.com/docs/portal)
