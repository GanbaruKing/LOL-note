# バックアップと復元

SettingsからJSONを保存・復元する。バックアップ形式は `format: "lol-note"`、`version: 2`。DBスキーマのバージョンとは独立する。旧version 1も読み込める。v1にはノートブックが含まれないため、復元するとノートブックは空になる。v2は旧アプリでは復元できない。

## 対象

- matchups：自分・相手・Role、難易度、評価、更新日時
- matchup_notes / champion_notes：本文、カテゴリー、Pin、ID、作成・更新日時
- champion_counters：チャンピオン対策と更新日時
- champion_pool：レーン別登録と自信度
- my_picks：Comfort Picksの登録
- knowledgeBook：章、記事本文、所属、順序、お気に入り、更新日時。DBではsettingsの専用キーに保存。

カタログ・Leagueのフォルダー設定・試合履歴・LCU認証情報は含めない。別PCでもカタログにあるチャンピオンなら復元できる。未対応IDがある場合はアプリ更新が必要。本文は平文なので、バックアップの共有先は利用者が選ぶ。

## 復元の保護

1. Main側でファイル選択、50MB上限と形式・値を検証。最大10万行。
2. 現在の内容を置き換える確認を表示。初期選択はキャンセル。
3. 現在のノートを `userData/backups/before-restore-<時刻>-<UUID>.json` に自動保存。保存できなければ復元しない。
4. ホワイトリストの6テーブルとノートブック専用設定を単一SQLiteトランザクション内で置き換える。外部キー・重複制約に違反した場合は全変更をロールバックする。
5. 画面のノートとプールを再読込し、自動退避先を表示する。

自動退避ファイルも通常の「バックアップから復元」で選べる。自動削除は行わない。復元はマージではないため、空のバックアップを復元するとノートと登録も空になる。

保存は同じフォルダーに一時ファイルを書き終えてからrenameする。処理中は他の書き込みIPCを拒否する。ファイル内容や任意SQLをRendererへ渡さない。

検証：全6テーブルの往復、日時・Pin・評価の保持、設定の保持、空データの復元、不正形式・重複・未対応ID・孤立ノートのロールバック、設定画面の保存・キャンセル・不正JSON拒否・自動退避をテストする。
